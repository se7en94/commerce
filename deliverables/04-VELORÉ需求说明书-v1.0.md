## 0. 关键问题速览（本文件最核心的部分）

在进入细节之前，以下 **4 件事决定项目能否成立 / 技术栈如何选择**。务必在下一轮沟通中优先解决。

### ❌ 问题 1：技术栈存在根本性冲突

客户回复 5.3 明确写道：
> *"VELORÉ 技术团队请在 **Next.js** 独立站中规划并实施"*

但我方之前所有方案、本地 POC、技术计划均以 **WooCommerce（WordPress）** 为基础。两者是完全不同的技术栈：

| 维度 | WooCommerce（我方方案） | Next.js + 自研后端（客户要求） |
| --- | --- | --- |
| 开发周期 | 快（1–3 周出 MVP） | 慢（2–3 个月起） |
| 运营门槛 | 低（后台可视化管理） | 高（需要开发资源） |
| 定制自由度 | 中（受限于 WP 架构） | 高 |
| 电商成熟度 | 成熟（支付/物流/多币种均有现成插件） | 需从零对接支付/物流/订单管理 |
| 报价数量级 | $15k–$45k | $50k+（且不含运维人力） |

**需要客户澄清的关键问题**（见 §12 待确认清单 #1）：
1. 客户提 Next.js 是**内部技术偏好**，还是确实要我方从零构建？
2. 有没有可能客户的 Next.js 技术团队负责前端，我方负责后端接口与电商逻辑？
3. 客户是否了解 Next.js 方案的开发周期和成本显著更高？

> **风险提示**：如果客户坚持 Next.js，我方之前所有基于 WooCommerce 的工作（本地 POC、主题定制、PPCP 对接）都无法复用。必须重新评估工期和报价。

### ⚠️ 问题 2：收款主体信息模糊

回复 2.1 写的是 *"PayPal 美国"*——这不是公司主体信息。PayPal 商家账户挂靠在一个合法注册的公司主体上，我们需要知道：
- 这家公司的全称和注册国家/地区
- 公司注册证明（营业执照或注册文件）

**这是支付通道申请的前置条件，没有它无法启动任何工作。**

### ⚠️ 问题 3：品牌授权材料能否提供

回复 2.4 写 *"不确定，需要建议"*——奢侈品类目申请支付通道时，承保审核要求提供品牌授权文件或货源证明。**材料缺失的情况下，通道大概率被拒。** 客户作为"多品牌零售商 / 买手"，比品牌方本身审核风险更高。

需要客户尽快明确：
- 哪些品牌有授权，哪些没有
- 没有授权的品牌，能否提供进货发票或采购凭证作为替代
- 如果没有任何品牌材料，是否愿意调整产品策略或接受通道拒批的风险

### ⚠️ 问题 4：无承运商账号，但需要物流追踪闭环

回复 3.2 写 *"无"*——没有承运商 API 凭证，物流轨迹自动回传无法落地。客户的供应链流程（下单 → 付款 → 供应商发货 → 物流追踪 → 退货退款）中，物流追踪是关键一环。

需要客户决定：
- 是否在项目启动前申请承运商账号（DHL / FedEx / UPS / 云途 / 4PX 等）
- 如果暂时没有，是否接受先用手动填写运单号 + 聚合查询（AfterShip / 17TRACK）的降级方案

> *"客户下单 → 我们付款 → 供应商发货 → 物流追踪 → 退货退款"*

## 9. ⭐ 客户补充的非标功能（原表单未覆盖）

客户在最后一题（"还有哪些重要事项"）中提到一个**原需求确认清单未覆盖**的核心功能：

> *"客户进入网站需要注册账户，注册账户需要填写邀请码，邀请码需要找客服人员。同时注册账户之后会要求客户填写收货地址。其他功能和购物网站一样的。"*

这是一个**会员邀请制**的访问门槛。默认 WooCommerce 不具备此功能，需要定制开发。需进一步明确：

- 邀请码由谁生成？批量还是单个？有效期多久？
- 已有账号是否可以跳过邀请码？
- 邀请码失效 / 误填的处理流程是什么？
- 是否需要邀请码统计（谁邀请了谁、转化了多少订单）？

**这个功能会显著增加开发工作量**，报价时必须计入。

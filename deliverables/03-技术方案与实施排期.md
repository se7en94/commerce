## 2. 目标架构（多市场可扩展）

```
买家 → CDN/WAF → WordPress + WooCommerce (HPOS)
                      ├── 主题层：多语言 / 多币种 / 奢侈品视觉
                      ├── 支付层：PPCP(PayPal) [+ 备选收单通道]
                      ├── 履约层：运费规则 / 关税(DDP|DDU) / 库存
                      └── 物流层：承运商 API → 轨迹聚合 → 状态回写 → 邮件通知
                                                          ↓
                                              订单状态自动流转（发货/签收）
```

**关键设计原则**：支付与传统物流都要做成**可替换的适配器**。因为目标市场未定，通道和承运商大概率会变，不要把业务逻辑焊死在某一家上。

## 3. 支付方案

### 3.1 主线：PayPal（PPCP）

你已配置好 WooCommerce PayPal Payments，它同时覆盖：
- PayPal 钱包
- Pay Later / 分期
- **Advanced Card Processing（ACDC）** —— 即站内直接收信用卡，无需跳转

这意味着**一条通道就能覆盖大部分市场的卡 + 钱包支付**，是多市场冷启动的最优起点。

### 3.2 但必须先解决三个前置问题

| 问题 | 说明 | 你要做的动作 |
| --- | --- | --- |
| **商户主体** | PayPal 商业账户的注册国决定可提现币种、结算路径、Seller Protection 范围。大陆主体做跨境收款有结汇限制 | 向客户书面确认主体注册地，并要求提供注册证明 |
| **高风险类目审核** | 奢侈品/时尚是通道重点关注类目，需品牌授权 + 货源证明 | 索要品牌授权书、进货发票，作为通道申请材料归档 |
| **资金冻结风险** | 新账户 + 高客单价订单，风控常做 21 天资金留存 | **必须书面告知客户**，让客户预留周转资金。这是上线后最容易扯皮的点 |

### 3.3 备选与分散通道（奢侈品项目强烈建议）

单一通道对奢侈品项目风险过高（一次封号 = 全站停摆）。建议方案里预留：

- **Stripe**（需港/新/美主体）—— 卡支付覆盖率与转化率优于 PayPal 跳转
- **Adyen / Checkout.com** —— 企业级，承保审核严格但稳定
- **聚合收单**（Airwallex / 万里汇 / PingPong / Asiabill）—— 大陆主体的现实选择，但费率高、体验参差
- **Klarna / Afterpay** —— 欧洲、中东分期刚需

> 报价策略：把「支付通道申请协助」**单独列为交付项**，并在 SOW 写明"通道审核结果由服务商决定，不保证通过"。这一句话能救你一次。

### 3.4 高客单价必须做的支付兜底

奢侈品客单价高，一次支付失败就是几百上千美元的损失。必须实现：

- 支付失败**明确提示原因**（而非静默返回），提供重试入口
- 3DS/SCA 挑战流程（欧洲强制）完整支持并测试
- 订单**幂等处理**，防止重复扣款
- 支付回调（webhook）失败时的**补偿轮询**机制
- 异常订单自动告警到你的监控渠道

## 4. 物流方案（三档阶梯，按客户成熟度选）

| 档位 | 方案 | 适用 | 成本/复杂度 |
| --- | --- | --- | --- |
| **L1 基础** | WooCommerce 官方 Shipment Tracking，手动填运单号 | 订单量小、起步阶段 | 低 |
| **L2 推荐** | Advanced Shipment Tracking (AST) 或 AfterShip / 17TRACK，自动抓取多承运商轨迹 | 多承运商、订单量中等 | 中（插件年费） |
| **L3 完整** | 承运商 API 直连（DHL / FedEx / UPS / 顺丰 / 云途 / 4PX）+ 状态回写 | 订单量大、需自动化 | 高（需客户提供 API 凭证） |

**必做的闭环**（不管哪一档）：物流轨迹要**反向回写订单状态**——发货自动转「已发货」、签收自动转「已签收」，并触发对应邮件通知。只做一个轨迹查询页而不做状态流转，是最常见的半成品。

**奢侈品特有要求**：保价、强制签收（high-value 订单签名是 Seller Protection 的前提）、白手套配送选项、退换货标签。

**关税模式**必须提前定：DDP（卖家包税）需要在结账页预收关税，运费规则与页面复杂度都会上升；DDU（买家自付）则要在结账页与运费说明里做显著提示，否则会产生大量纠纷。

## 5. WooCommerce 侧配置与插件清单

### 5.1 必须先开启的能力

- **HPOS（高性能订单存储）**：WooCommerce 7.1+ 内置，高订单量下必须开启
- **多币种展示**：WooCommerce Currency Switcher (Aelia) 或 CURCY
- **多语言**：WPML 或 Polylang（中东市场需 RTL 支持）
- **税率**：WooCommerce 内置 Automated Taxes 或 TaxJar（欧洲 VAT / 美国 Sales Tax）
- **结账页优化**：使用 Block Checkout，减少高客单价场景的跳出

## 6. 合规清单（多市场）

- [ ] 隐私政策 + Cookie 同意（GDPR / CCPA）
- [ ] 退换货条款页（奢侈品通常有特殊条款）
- [ ] 关税/VAT 提示（DDP/DDU 必须显式告知）
- [ ] 支付页 PCI-DSS 合规（用 PPCP/Stripe 托管表单即可规避大部分责任）
- [ ] 数据跨境传输合规（客户数据存哪儿要确认）
- [ ] 无线电商品，无需 FDA/FCC 认证

> 明确边界：**你负责技术实现与合规提示，不承担税务与法律合规责任**。建议在 SOW 里写明"税务与法律事宜由客户指定的当地顾问确认"。

## 8. 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 支付通道被拒 | 中高 | 阻塞收款，项目无法上线 | 提前索要品牌授权材料；准备 2 家备选通道；SOW 写明不保证通过 |
| 账号资金冻结 | 中高 | 客户现金流受影响，归咎于你 | 书面提前告知；建议客户预留周转；尽早建立交易记录 |
| 客户素材延迟 | 高 | 排期全面顺延 | 排期以素材就绪日为基准；未齐不启动；变更流程处理 |
| 承运商 API 不稳定 | 中 | 轨迹显示异常 | 保留 L1 手动方案作为降级路径，不阻断下单 |
| 多市场合规变更 | 中 | 工作量增加 | 变更流程；建议客户聘当地顾问 |
| 需求蔓延（Scope creep） | 高 | 利润被吃光 | SOW 明确不含项 + 变更单价，书面确认才开工 |
